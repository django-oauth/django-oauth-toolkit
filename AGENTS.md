MUST keep `constrain_package_deps` and `use_frozen_constraints` in `[testenv]`, and an env that overrides them or installs dependencies another way MUST pin Django itself. When adding or changing a tox env, its `deps` or `extras`, or a dependency's version bounds, MUST check that each affected env installs the Django it names: `.tox/<env>/bin/python -c "import django; print(django.get_version())"` after `tox -e <env> --notest` (or add `--list-dependencies`), or, on CI, the comma-separated package list tox prints just before the env's `commands[0]>` line.

Remove a version gate once the minimum supported Django makes it always true or always false.

- MUST place new code in the correct OAuth2-role package and follow the layout rules in `docs/package_layout.rst`. In short:
  - Authorization-server / OpenID Connect Provider code goes in `oauth2_provider/authorization_server/` (OIDC under `authorization_server/oidc/`); resource-server code in `oauth2_provider/resource_server/`; client-side code in `oauth2_provider/client/`; genuinely shared plumbing in `oauth2_provider/core/`. MUST NOT add new top-level modules.
  - Name a package for the **protocol role its code plays on the wire**, using the vocabulary of the spec that *defines* that role. OAuth2 (authorization server / resource server / client) is the base vocabulary because only it names every role this library implements; a spec that *specializes* a role becomes a facet one level down (OIDC's OpenID Provider is `authorization_server/oidc/`; its Relying Party would be `client/oidc/`); a spec introducing a role OAuth2 lacks (e.g. OpenID Federation's Trust Anchor) earns its own package under that spec's name.
  - Pick the package by which side of the wire the code runs on, not by which side it *mentions*. `oauth2_provider/client/` is *only* for code this library runs **as** a client against some authorization server (today: RFC 7523 `make_client_assertion`), and MUST stay standalone — no `authorization_server` imports, no app-registry or model access. Registering clients (`dcr`, `cimd`) and the OP's `RP-Initiated *` endpoints are provider code and MUST NOT be filed under `client/`.
  - MUST import canonical role paths from first-party code, never the deprecated top-level shim modules (importing a shim emits a `DeprecationWarning`).
  - MUST NOT relocate `models.py`, `generators.py`, or `validators.py` (migration `deconstruct()` freezes their import paths), and MUST keep `oauth2_provider.oauth2_validators.OAuth2Validator` importable from its current path.
  - When moving a module/symbol, MUST leave a backward-compatible shim at the old path that emits a `DeprecationWarning` (silent only when a framework imports it at startup, e.g. `oauth2_provider.admin`), repoint all first-party imports/settings defaults to the canonical path, and add a CHANGELOG `Deprecated` entry.
  - MUST verify a reorganization is behavior-neutral: full pytest suite passes with no first-party `DeprecationWarning` on import, `manage.py makemigrations --check --dry-run` reports no changes, and old import paths still resolve to the same objects (`tests/test_import_compat.py`).
